01 · The frame

The signal budget

Accuracy is a poor yardstick here because the home team wins ~53% of games for free. The useful question is how much information a model adds over that free baseline, measured in nats of log-loss. Doing it on one consistent sample makes the whole ten-year project legible at a glance.

02 · Lineage

V1 through V10

Each generation added features and reported a gain. The pattern worth seeing is that reported validation accuracy rose steadily while true out-of-sample accuracy barely moved — the gap between the two is the project’s recurring lesson.

The documentation contradicts itself — read it with care

Three different numbers exist for V10’s live 2026 accuracy. MODEL_EVOLUTION_COMPLETE.md says 54.7%. V10_EXPERIMENT_COMPLETE.md says 61.48%. Measured directly against 1,763 genuine pregame predictions, it is 53.72%.

The 61.48% figure came from 283 early-season games scored with retrospectively rebuilt Statcast features that were not knowable at first pitch. Feature counts disagree too (V8 is variously 89 and 112). Treat the per-version doc numbers as optimistic and the evolution doc as closer to right.

08 · Where it stands

The honest position

The pipeline is sound: batch-only writes, an auditable feature row per prediction, a clean year split, no team-identity features after the V8 post-mortem. Ten generations of work produced a system that runs reliably and predicts at roughly 54% live.

The reason it stopped improving is not a modelling failure. Every experiment that failed, failed for the same reason: the market prices everything in the box score and everything in the public injury report. New public information does not help — weather and IL status both measured null. A better estimator of information already held does not help either — the Kalman filter tied Elo exactly. And 450 trials of automated search over 174 features converged on a three-column logistic regression.

What is left is not another feature. It is either a market we have not tested (totals, where temperature is a confirmed 1.48-run signal), or information that is genuinely unpriced — which realistically means acting on a lineup scratch or weather shift before the line moves. That is a latency problem, not a modelling one, and it is a different project.
